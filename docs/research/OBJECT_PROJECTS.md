# 自然照片识别：开源项目代码调研

调研日期：2026-11-12。起因是用户上传的真实手写照片识别失败，并要求改为更通用的图片识别。以下区分阅读、采用和未实现的部分；没有把上游的指标写成本项目成绩。

| 项目 | 实际阅读内容 | 可借鉴之处 | 本次处理 |
|---|---|---|---|
| [Ultralytics](https://github.com/ultralytics/ultralytics/tree/v8.3.40) | `engine/predictor.py`、`data/augment.py` 的 LetterBox、`models/yolo/detect/predict.py`、依赖声明 | 等比例缩放补边，保留边缘主体；阈值与 NMS；检测框映射回原图；模型一次加载 | 采用官方库 8.3.40 和官方 YOLO11s COCO 权重，CPU 推理，不自行重写检测算法 |
| [Grounding DINO](https://github.com/IDEA-Research/GroundingDINO) | README、`groundingdino/util/inference.py` | 图片加文字提示；分别过滤框分数和文字分数；坐标恢复 | 未安装、未实测。需要额外文字模型和运行依赖，本轮不把可运行性当成已经验证 |
| [OpenAI CLIP](https://github.com/openai/CLIP) | README 零样本示例、`clip/clip.py` | 图片与候选文本分别编码；配套预处理；下载权重做 SHA 校验 | 未采用。它比较给定候选名称，不会自动列出所有物体；不应把候选间 softmax 当真实正确率 |
| [Supervision](https://github.com/roboflow/supervision) | README 的模型适配、标注器、数据集示例 | 将检测结果统一为坐标、类别、分数，渲染与模型分离 | 借鉴结果结构；前端 Canvas 绘制编号框，不引入整套标注依赖。尝试读取旧路径 detection/core.py 返回 404，因此不声称已审阅该文件 |

阅读文件的 URL 和 Git blob 摘要另存于 `OBJECT_SOURCE_FILES.json`。固定 tag 避免未来升级改变已核对的行为；没有使用“最新一定更好”的假设。依赖安装用现有 requirements 作约束，保持 torch 2.2.2、torchvision 0.17.2 和 numpy 1.26.4 相互匹配。

## 对当前项目的具体改变

原流程只能问“整张图最像哪个数字”。第一次改造接入 ResNet50，但仍然只给整张图一个主标签，会把多人、多物体和类别外图片强行塞进一个类别。这一步不是最终解决方案。

采用检测后，主结果是零个或多个物体，每个都有框、名称和分数。输入保持 RGB，先纠正照片方向；库内部 letterbox 到 640 输入尺度，再把预测框恢复到输入坐标。用户框选局部时，额外把局部坐标转换回整张原图，前端和导出使用同一份归一化坐标。

ResNet50 仍作为折叠的辅助分类，不与检测模型混合分数，也不在检测空结果时顶替成主结果。80 个检测类别是常见物体；1000 个分类类别包含更多细分类别，两者不是“1080 类检测”。人工确认与模型原始结果分开存储，方便追查误报。

## 验证办法与尚未解决的事

先在同一组公开真实照片上对比两个流程，成功和失败都保存。它们是公开示例，不能证明与预训练数据独立，因此只算冒烟检查，不算泛化准确率。下一步真实验收应由使用者提供未提前挑选的日常照片，逐框标注漏检、误检和类别错误；不能拿几张展示图算“准确率”。

当前仍不支持 OCR、任意名称识别、自动理解照片中所有内容。低阈值会增加误报，高阈值会漏掉物体；本次使用 0.35 作为明确记录的展示阈值，没有按五张示例反复挑选最优值。Grounding DINO 是后续开放词汇方向的候选，不是本轮已完成能力。
