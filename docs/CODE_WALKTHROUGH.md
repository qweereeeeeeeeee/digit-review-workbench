# 技术与代码说明：从上传一张图片讲起

这份说明对应当前仓库。建议先读项目说明，再对照这里打开代码；不要求一开始就理解每一行语法。

## 先分清三个部分

浏览器页面负责选图片、显示方框和让人修改结果；后端负责接收请求、调用模型、存记录；模型负责根据图像计算预测。页面显示正常不等于模型一定识别正确，服务能启动也不等于真实照片测试已经通过。

当前主要入口是 `objects/`。原考核训练在 `src/`，原数字复核页面在 `workbench/`。保留两个入口是因为手写 ResNet 对应基础训练要求，而通用图片识别属于拓展。不能把两套模型的结果混着解释。

## 第一步：页面把图片交给后端

`objects/web/app.js` 读取用户选择的文件，把字节编码成 Base64 字符串，连同文件名、请求编号和可选框选区域发给 `POST /api/recognize`。Base64 只是传输表示，不会把图片变成识别答案。

`objects/api.py` 定义接口和输入格式。每次识别都有请求编号，同一个编号重复发送相同内容，会返回以前的回执；同一个编号换了内容则拒绝，避免重试产生含糊记录。这不等于自动删掉用户每一次重复上传的照片：新编号代表一次新的操作。

## 第二步：先确认图片可以处理

`objects/engine.py` 中的 `decode` 检查文件是否能解码，只接受 JPEG、PNG、WebP 单帧图，限制为 10 MB 和 2000 万像素，宽高至少 32 像素。它还纠正照片方向，把透明背景合成白色，并拒绝几乎纯色的输入。

框选区域采用相对坐标，必须在原图内。框选后的结果最终要还原到原图位置，否则页面会画错方框。`tests/test_general.py` 对坐标还原、无效框及文件摘要做检查；这些测试验证程序行为，不测量模型识别准确率。

## 第三步：分别识别物体和文字

`objects/general.py` 加载固定版本的 Florence-2 和 PP-OCRv5。加载前先把每个模型文件重新计算摘要，与来源清单比较，避免文件损坏或版本不一致。

Florence-2 根据图像生成区域描述和位置；PP-OCRv5 先定位文字区域，再读取字符。数字也是字符，所以能读取一串数字，而不是强制把整幅照片判成单个 0–9。两者独立执行，因此可能一个分支读出 `8`，另一个分支却描述成字母 B。系统保留这种分歧，供人检查。

旧 YOLO11s 和 ResNet50 也会产生对照结果，放在页面折叠区域。它们不和新模型投票得出一个伪造的高分。Florence 区域没有提供校准置信度，代码返回 `score=None`；OCR 得分虽来自模型，也不是图片正确概率的保证。

模型在服务启动时加载一次，后续请求复用。推理有锁保护，避免同一实例同时执行相关计算；这会使请求需要等待，不等于已实现高并发服务。本机 CPU 速度有限，十几到几十秒属于这次实际运行现象。

## 第四步：保存原预测，让人可以纠错

`objects/store.py` 使用 SQLite。`records` 表保留原图、文件摘要、模型结果、最终人工标签和版本号；`reviews` 表记录修改前后状态与备注；`receipts` 表保存重复请求的回执。

模型结果与人工标签分开。比如图中一把勺子被框两次，使用者可以把最终结果写成“咖啡杯、勺子”，但原始三个区域还在。以后检查模型问题时，能区分“模型本来就识别对”和“人改对了”。

保存时检查版本号。两个页面都打开版本 0，先保存的把它改成版本 1，后保存的不能直接覆盖，应重新读取。接口返回 409 是冲突提示，不是模型没认出物体。

422 则表示输入没有通过接口验证。例如确认结果要求非空标签，但真实故障仍应查看返回的 `detail` 才能确定原因。用户现场录屏出现了 422，单凭录屏不能断言是哪一个字段造成，不能把猜测写成修复结论。

## 手写 ResNet 的训练代码怎样看

先看 `src/data.py`：数据从哪里来，怎样归一化、划分并保存。接着看 `src/model.py`：卷积分支计算特征，shortcut 保留输入，两路相加；尺寸变化时先用投影匹配。

再看 `src/train.py`：把一批图送入网络，计算损失，反向传播得到梯度，优化器更新参数。验证集用来选择权重，测试集用于最后报告；校准集另外用于概率温度和提示阈值。训练会改变权重，普通上传识别不会训练网络；保存人工纠正也不会自动让模型学会这张图。

训练产物在 `artifacts/run-001/`。`history.csv` 是每轮记录，`predictions.csv` 是逐张预测，`errors.csv` 留下错误。`scripts/verify_artifacts.py` 从真实权重重新算预测，再与这些文件核对。看懂结果时要连同数据范围一起看，不能把小图测试成绩说成手机照片成绩。

## 答辩时可以沿着这条线说明

先展示基础残差网络和训练文件，说明这部分满足手写模型要求；再上传实际照片，指出物体与文字各由什么模型处理；最后打开原预测和人工修改记录，解释为什么保留错误。

遇到识别不准，先检查原图、取景和模型输出，再判断是否是能力不足。遇到请求失败，先看状态码与返回信息。遇到页面打不开，检查进程和健康接口。三类问题不能都归结为“模型准确率低”。

能够复述这份说明不等于已经掌握代码。建议本人实际完成一次上传、一次复核、一次查看失败返回，并找到对应函数；只陈述自己真正做过和理解的内容。
